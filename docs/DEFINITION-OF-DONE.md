# InferLab measurable definition of done

These are future MVP release gates, not tests run or passed by this documentation task. The owner records commit/release ID, date, environment, command or manual procedure, expected/actual outcome, and evidence for each gate. Synthetic fixtures must be labeled DEMO DATA; real hardware measurements are required only for the explicit benchmark gates.

| ID | Gate | Required evidence / pass criterion |
| --- | --- | --- |
| D01 | Public reading independent of laptop | Power off local API, worker and engines. In a fresh browser with cache disabled, load overview, reports/detail, models, comparison, methodology and JSON download from Pages; all succeed, and browser network log shows zero requests to local/private services. |
| D02 | Publication boundary | Create one unpublished experiment and publish a different completed report. Inspect every deployed JSON asset and manifest: zero unpublished IDs, credentials, private prompts, local paths or raw logs. Before first publication, public UI shows an honest empty state. |
| D03 | Single-admin authorization | For every private route, anonymous/expired sessions return 401; a non-admin identity is denied. Anonymous login attempts cannot create a session without the provisioned credential. Public mutations cannot queue/cancel/publish; no GPU job starts from public requests. |
| D04 | Session/origin controls | Verify local HTTPS, Secure/HttpOnly/SameSite cookies, 12-hour expiry, logout invalidation, invalid Host rejection, rejected foreign Origin/CSRF requests, and failed-login throttling after 5 failures/15 minutes including API restart. No wildcard credentialed CORS. |
| D05 | Validated resource bounds | Test each config minimum/maximum and one value beyond each bound; oversized bodies, unknown registry IDs, shell/path/URL inputs and input-plus-output context overflow are rejected. Eleventh pending job/submission above daily cap is rejected; no automatic model download occurs. |
| D06 | Queue durability and idempotency | Same submission key/body twice yields one job; changed body with same key yields 409. Restart API before claim and verify job persists. Start two worker processes and prove no more than one active GPU job. |
| D07 | Worker availability and interrupted recovery | Heartbeats at 30 seconds; UI reports offline after 90 seconds plus at most one 10-second poll. Kill/suspend worker mid-run; expired lease is reconciled on next API/worker access after 120 seconds, partial runs never complete, stale token is rejected. Unconfirmed engine stop pauses queue. |
| D08 | Bounded retries and completion | Induce transient failure: at most two attempts/job with at least 30-second retry delay. OOM/validation/checksum/timeout failures do not retry automatically. Duplicate completion saves one set of runs; conflicting/stale completion cannot overwrite it. |
| D09 | Cancellation, timeout and stop switch | Cancel queued and running jobs; responsive worker stops active inference within 30 seconds, saves cancelled state and excludes partial metrics. Race cancellation against completion: exactly one wins and a cancelled job cannot complete. One-hour deadline terminates a job. Pause blocks new claims and survives worker restart until explicit resume. |
| D10 | Honest measurements and reproduction | Publish at least one actual Ollama benchmark with 2 warmups and 10 measured repetitions, documented warm/cold conditions, streaming TTFT, units, counts/errors and full PRD provenance. Another engineer follows the report to execute the same pinned workload; no fabricated values or unsupported speedup claim. Numeric equality across machines is not required. |
| D11 | Public analytical accuracy | Every displayed metric traces to saved accepted run IDs. A matched comparison shows controlled variables; a mismatched pair is flagged. Missing measurements display unavailable, not zero. Warm/cold data stay separate; demo data is visibly labeled wherever shown. |
| D12 | Publish safety and failure recovery | Reject malformed schema, secret/path canary, missing provenance and checksum mismatch before deploy. Approve exact preview hash; deploy and verify manifest/reports. Simulate failed build/deploy: previous release remains readable. Demonstrate rollback and document that withdrawal cannot recall downloaded copies. |
| D13 | Usability and responsiveness | At 375 px and 1440 px widths, core pages have no page-level horizontal overflow; tables may scroll within their container. All forms/navigation work by keyboard with visible focus. Exercise loading, empty, offline, validation and server-error states; no false success message. |
| D14 | Free hosting and CPU-only checks | Record account plan/usage and successful asset/build-budget preflight against ADR-001. Verify no paid services, Functions, hosted GPU jobs or frontend secrets. Required contract/security/UI tests run on CPU with deterministic fixtures and no model downloads. |
| D15 | Audit, backup and incident handling | Verify submission/cancel/retry/login/publication audit records and stated retention. Restore latest database and release bundle into a clean local environment within 1 hour, with backup age <=24 hours during active operation. Document stop, credential rotation, withdrawal and recovery procedures. |

Release passes only when all D01-D15 have evidence, no critical/high security finding remains open, and the owner approves the reviewed public payload. Optional stretch features cannot substitute for a failed MVP gate.

For this specification-only task, completion means the [PRD](PRD.md), [architecture](ARCHITECTURE.md), [zero-cost ADR](ADR-001-zero-cost.md) and this checklist exist, agree on scope and access boundaries, cite the supplied rulebook, and contain no implementation or invented benchmark measurements.
